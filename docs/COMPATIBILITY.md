# pandas compatibility

The target is pandas 3.0.5. Full behavioral parity and exact pandas output
matching have **not** been achieved. The 505-name census only checks whether
an API name exists.

## Evidence

| Check | What it establishes | Current result |
| --- | --- | --- |
| `bun run parity` | Presence of tracked API names | 505/505 |
| `bun run compatibility:test` | Focused pandas-derived values, selected Series labels/names and categorical metadata | 524 value/metadata cases and 528 explicit dtype cases pass |
| `bun run conformance` | Ten operation families under the paper's declared comparison rules | 2,500/2,500 for pandas/adaptive and each backend comparison |
| `bun run conformance:strict` | Exact serialized observations, native dtype strings, exception types/messages and row order | Fails; exact compatibility is not established |

[API-COVERAGE.json](API-COVERAGE.json) lists every tracked name separately.
`partial` means that some contracts have tests; `unverified` means that neither
of these pandas-oracle suites exercises that API. Neither status means complete
compatibility. Ordinary library unit tests are additional regression protection,
but are not counted as independent pandas-oracle evidence.

The focused fixture is generated by
`scripts/compatibility/generate-oracle.py` using pinned pandas. Run
`bun run compatibility:fixtures` to regenerate it, then review the diff and run
`bun run compatibility:test`. Tests run offline from the committed fixture.
They compare finite numbers with zero tolerance and preserve negative zero.
Their declared transport maps missing scalars to null, NumPy scalars to JSON
values, and Series to lists or selected metadata. This transport is **not** an
exact match of native pandas types or missing-value representations.

The paper corpus uses absolute and relative floating tolerance of `1e-9`,
compares broad dtype families, and permits duplicate-match permutations within
unchanged merge-key groups. Strict mode removes those comparator relaxations.
Both modes still observe the explicitly adapted operations in `run-pandas.py`
and `run-bun.ts`; they do not cover every public return type, warning, parameter,
or dtype. For example, the paper's DataFrame `value_counts` adapter resets the
pandas result index. That adapter is not proof of native return-type parity.

Live study outputs go to `out/conformance` or `out/strict-conformance`. The
frozen manuscript evidence in `paper/data/conformance` is preserved. Strict
reports use `summary-strict.json` and `mismatch-ledger-strict.json`. A mismatch
causes a nonzero exit. `--report-only` writes findings without failing; it must
not be used as a correctness gate. Empty, duplicate, missing, and unexpected
case observations are rejected even in report-only mode.

The separate dtype fixture (`generate-dtype-oracle.py`) compares explicit dtype
names and values, preserving `NA` and `NaN` separately. It covers constructors
and casts for numeric widths, nullable numeric types, `bool`, `boolean`,
`string`, and `object`. Error cases currently assert rejection, not exact error
classes/messages. Integers outside JavaScript's safe range are rejected until
exact bigint storage is implemented. Default dtype inference and propagation
through all operations remain incomplete. `number` and `date` remain legacy
conversion aliases.

## Changes to existing behavior

The pandas-oracle tests required changes to earlier library contracts:

- Explicit `boolean` casts now require bool-like values; strings such as `"false"`
  are rejected. `string` casts use pandas boolean spelling (`"True"`/`"False"`)
  and represent missing values with `NA`.
- `get_dummies` sorts categories, returns booleans by default, retains the input
  index and empty-frame columns, excludes missing categories, and implements
  `dummy_na`. `dtype: "number"` retains numeric indicator values. `drop_first`
  removes the first sorted category.
- Categorical inference retains scalar types and excludes missing values.
  Explicit categories reject missing or duplicate entries. Unordered dtype
  equality ignores category order; ordered equality preserves it.
- Factorization excludes missing values and treats booleans and equal numeric
  keys consistently in both entry points.
- Empty or all-missing Series sums and products return 0 and 1. Constant Series
  skewness and kurtosis return 0 when enough observations exist.
- Series and DataFrame rounding use ties-to-even. Series monotonicity checks
  strings and missing values. Negative head/tail counts and `tail(0)` follow
  pandas. `duplicated` preserves the Series name; missing `between` results
  are false.
- String operations propagate missing results for non-string inputs. Tested
  Unicode operations use code points. `contains` defaults to regex matching,
  `match` starts at position zero, and `count` counts regex matches. Out-of-range
  string `get` returns null. Capitalization and signed zero-padding are corrected.

These changes are unreleased. The immutable v0.4.1 release retains its original
behavior and measurements.

## Remaining work for full parity

1. **Dtypes and missing scalars.** Shared missing detection and typed NA/NaT
   sentinels and explicit cast metadata are implemented. Complete physical
   storage, default inference/promotion rules,
   nullable masks, and exact integer support. Distinguish NaN, NA, NaT, and
   Python object null where required. Preserve metadata through every operation.
2. **Index and output contracts.** Integrate Index/MultiIndex into DataFrame and
   Series storage. Implement names, levels, duplicate labels, alignment, native
   reduction return shapes, and tuple labels. Existing array wrappers do not
   establish MultiIndex compatibility.
3. **Datetime and categorical integration.** Preserve timezone and categorical
   metadata through Series/DataFrame operations. Implement DST ambiguity and
   nonexistent-time rules, precision units, and extension dtypes.
4. **API breadth.** Expand parameter combinations and boundary cases for every
   `partial` or `unverified` API in the inventory, including GroupBy, windows,
   IO formats, mixed data, and alignment. Binary-format bridges require real
   format compatibility tests. Python and JavaScript regex semantics also need
   a declared compatibility strategy.
5. **Diagnostics and numeric exactness.** Compare warning categories, errors,
   floating reduction order, signed zeros, infinities, and mutation behavior.
   A finite test corpus cannot prove agreement for every possible input.

A release may claim full parity only against a declared version and supported
contract, with unsupported behavior listed explicitly and its strict gate
passing. Passing the name census or the focused fixture is insufficient.
